DevOps 管理需求与 Git 版本。IDE Agent 自行完成开发、全部测试的编写和执行，以及发布。

01 / 一次启动即可使用

docker compose up -d --build

容器健康后访问 localhost:8080，使用 admin / admin 登录。每次仍用默认密码登录都会提醒修改，可选择“本次忽略”。仅支持用户名密码。

一个容器包含 DevOps、Gitea、MySQL；只有 data 和 backup 两个 named volume。数据库、仓库、配置、密钥与日志在 data。Gitea 和 MySQL 不开放外部端口。

02 / 创建或导入项目

打开“创建或导入项目”，只需填写项目名称。仓库标识留空自动生成，也可填小写字母开头的字母、数字、连字符。空项目自动包含双方职责约定 agent.md。

已有项目选择“导入压缩包”，文件后缀不限。支持 ZIP、TAR 以及 gzip/bzip2/xz 压缩 TAR，最大 32 MiB。包根或单层仓库目录内须有非空 UTF-8 agent.md，不要求其他业务结构。

保留源码、二进制、隐藏文件、可执行位和原始 agent.md；忽略 .git、.devops 和 macOS 元数据。平台不执行包内代码。解压路径穿越、重复、链接、设备文件和超限内容会被拒绝。

03 / 直接记录需求与进度

新建需求时填写标题与说明，选择功能、缺陷或变更，设置优先级。状态可直接选待处理、进行中、已完成或已取消，保存后立即生效。需求被别人修改时会要求刷新，避免覆盖最新内容。

详情可创建关联分支，并查看关联版本。合并 PR 不会自动把需求改为已完成，完成情况由你或 IDE Agent 更新。

04 / 从工作分支到版本标签

  1. 在“分支与合并”从当前 main 创建工作分支，可关联需求。
  2. IDE clone/fetch 已有分支，完成开发、自行编写与运行全部测试，再通过 DevOps Git 网关快进推送。
  3. 从工作分支创建 PR，查看真实差异和提交 SHA。无冲突时点击“合并 PR”合入 main。
  4. 如果有冲突，页面列出 DevOps Agent 生成的文件差异：左侧是 main，右侧是工作分支。人类逐项选择左或右，只记录选择、不执行合并；IDE Agent 根据选择解决冲突并重新推送。
  5. 在“版本”登记标签，默认使用当前 main，也可选 main 历史中的完整 SHA。添加说明与关联需求。

版本是真实且不可覆盖的 Git 标签，不表示已经部署。DevOps 没有审批、测试门禁或发布任务，IDE 无需提交执行证明。

分支删除在独立确认页进行，必须没有待合并 PR。main 与 devops/control 受保护。所有远端分支创建、删除、合并与标签操作通过 DevOps API/UI；网关禁止直接创建分支、直推主线、强推和直接推标签。

05 / 同一身份，同一工作区

人类

负责人维护成员；成员管理需求与版本；观察者只读。冲突时由人类选择左侧 main 或右侧工作分支。

IDE Agent

按人类项目委托管理需求和版本，并自行完成全部开发、测试及发布。收到冲突选择后修改工作分支。

DevOps Agent

按人类委托维护需求，并提供 PR 的真实差异和冲突点报告，不执行冲突合并。

在“项目与授权”生成 1–24 小时委托，明文只显示一次。IDE Git 用户名填统一账号，密码填短时凭证。委托不超过人类当前项目权限，账号停用、成员移除或凭证撤销立即阻止后续访问。

git clone http://localhost:8080/git/<仓库标识>.git
export DEVOPS_URL=http://localhost:8080
export DEVOPS_PROJECT=<项目ID>
export DEVOPS_TOKEN=<短时凭证>
node /path/to/ai-devops/cli/devops.mjs workspace init
node /path/to/ai-devops/cli/devops.mjs workspace sync

根 agent.md 约定协作方式，CLI 将 .devops 加入本地 Git 排除列表。inbox/requirements 和 state.json 是只读投影，outbox 保存需求变更 JSON，receipts 保存回执。修改投影会停止同步，先保存个人修改并移除该投影文件后重试。

06 / 平台备份、升级与恢复

默认每天北京时间 03:00 冷备 data 到 backup，可在“系统运维”改时间或手动备份。备份时暂时关闭入口、排空请求、停止内部服务，形成一致归档。

docker exec <容器名> devopsctl backup

恢复会校验数据库、HMAC 审计链与 Git；撤销旧会话、委托，并将未决 Git 操作标记待核对。新生成的备份还校验标签。v1 升级前用旧容器备份，v2 会归档旧状态并保留项目、需求和 Git 历史。

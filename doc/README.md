# AI 辅助 DevOps 平台方案

面向 2–3 人、使用 AI 原生开发平台的小团队。当前已实现 P0 工作台并完成本地 API、浏览器、Compose、Gitea 和恢复验证；Phoenix 业务发布仍采用人工适配器。

- [P0 运行手册](./P0运行手册.md)
- [P0 验收记录](./P0验收记录.md)

- [平台设计方案](./AI辅助DevOps平台设计方案.md)：定位、范围、项目模板与初始化、项目工作流、AI 能力、Phoenix 工程适配、多环境发布、架构与实施计划。
- [P0 技术规格](./DevOps平台P0技术规格.md)：Docker Compose 部署、MySQL/Git/named volume、TypeScript 全栈、React + Ant Design、RBAC 三员、全流程 AI agent、审计查询和 Phoenix/JS/TS/CSS/SQL 变化可视化的实现基线。
- [研究依据与引用台账](./研究依据与引用台账.md)：Gartner 官方公开资料、逐条观点映射、仓库证据及引用边界。
- [团队交付流程模拟](./团队交付流程模拟.md)：三人团队从建项目、提 PR、审查返工、合并到 test/prod 发布的完整虚构演练（2026-10-01）。

建议先读设计方案的第 1、3、4、6、13、14 节，再核对研究台账。第 4 节包含项目模板组装和初始化；第 14 节专门评估企业定制软件背景下哪些能力偏轻、哪些首期偏重。当前方案以用户提供的《2026年十大技术趋势》PDF 第 5–6 页为正式引用，并以用户补充的 Gartner 第 22 页截图 `[U1]` 逐项核对生命周期能力；二者在台账中分开记录。方案日期为 **2026-10-01（Asia/Shanghai）**；后续演练的日期以各文档标注为准。

推荐方向：以项目为边界，以一次可交付的“变更”为工作单元，让 AI 覆盖计划、开发、测试、发布、配置和监视器六个位置；开发继续在外部 AI 开发平台完成。

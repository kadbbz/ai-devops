# P0 运行手册

日期：2026-10-02（Asia/Shanghai）。单机、小团队实现，不依赖 Redis。

## 部署与首次登录

1. 复制 `docker/.env.example` 为 `docker/.env`，使用随机且互不相同的 MySQL、Gitea、bootstrap 密码；文件权限设为 600。密码从宿主环境注入，不进入镜像。
2. 运行根目录 README 中的 Compose 命令。MySQL 首次初始化为 Gitea 创建独立 database 和连接用户；平台启动时执行带锁的版本化迁移。
3. 访问 `PUBLIC_ORIGIN`，使用 `admin` 与 bootstrap 密码登录并修改密码。bootstrap 仅在 users 表为空时有效，不会在重启时重置账号。三员角色由平台管理员授予。业务用户创建后也需首次改密。
4. 平台管理员创建项目并指定业务用户为负责人。负责人分配成员和干系人。负责人变更使用管理员专用接口，不通过成员角色接口转移。
5. 项目设置中预览和生成 Phoenix 模板快照，绑定仓库。生成的文件包需由团队按 diff 合并到仓库；平台不会直接覆盖受保护分支。

此工作区当前验证实例：平台 `http://localhost:18080`，Git `http://localhost:13000`。实际管理员密码保存在本机被忽略的 `docker/.env`，不放入验收记录。`test/compose-smoke.mjs` 首次运行会完成测试实例管理员改密，并同步此文件以便再次运行。

## 数据、事务与迁移

- 26 张业务表覆盖规格最小表集，并增加 sessions、policies、worker_heartbeats。JSON 保存可演进的领域内容，snake_case 生成列用于索引和查询；通过 Drizzle/mysql2 读写。
- P0 使用 MySQL advisory lock 串行化领域事务，包括部署环境锁和队列认领。适合 2–3 人小团队；Git 分析仍在请求事务中进行，最多 3000 个文件、单文件 300 KB、命令 30 秒。较大仓库应后续拆成异步分析任务。
- 业务事件拥有版本/指纹。需求、设计、base/head、finding、测试、环境/配置变化均参与批准有效性检查；原始记录留存。
- 未配置 DATABASE_URL 的普通运行必须显式设置 STATE_FILE。文件模式仅用于本地开发，禁止多进程共用；独立 worker 生产部署必须用 MySQL。
- 遇到旧演示 schema 会以 `MIGRATION_REQUIRED` 停止，不会自动执行破坏性升级。先备份、保留旧库，再在新 database 初始化并显式迁移需要保留的数据。

## AI 与任务

配置 `AI_BASE_URL`（包含 `/v1`）、`AI_PROVIDER`、`AI_MODEL`、`AI_API_KEY`。实现兼容 Chat Completions JSON 模式，服务端继续使用共享 Zod Schema 验证七种任务的必需字段。当前验收使用本地 HTTP 契约服务，不代表任何真实付费模型已联通。

安全管理员按项目开放提供方、文件类型、上下文长度、输出长度和预算。未知真实费用以单次预算预留估计计费，不把它展示为真实账单。输入和输出均扫描疑似凭证，`${ENV_NAME}` 引用允许通过。执行前重新读取当前安全策略，防止已排队任务使用撤销的权限。模型不能请求任意工具、shell、角色变更或发布动作。

worker 通过数据库串行认领、60 秒租约、15 秒心跳运行任务。进程被中断后 queued 任务继续执行；过期 running 任务标记 expired，用户可人工重试。后台运行失败不会生成通过的测试或发布记录。

## Git 与测试适配

Git Clone 地址必须匹配 `GIT_BASE_URL`。`credentialRef` 只能引用 `GIT_*` 环境变量，凭证通过 Git 的进程环境头部使用，不写入仓库配置。Gitea PR 通过 API 获取 base/head，分支和 PR 事实来自 Git。开发测试可显式启用 `ALLOW_LOCAL_REPOSITORIES=true` 导入本地样例，生产禁止本地路径。

在项目中登记测试 `commandRef`，由运维将对应的命令白名单 JSON 挂载至 worker `/etc/devops/test-commands.json`，或设置 `TEST_COMMANDS_FILE`。样例见 `docker/test-commands.example.json`。程序与参数数组分离、`shell:false`，测试环境只传 PATH 与 CI，不继承模型/数据库凭证。测试代码本身仍须来自可信团队仓库；P0 单 worker 不作为运行任意陌生代码的沙箱。

人工报告可上传文本或附件；测试结果必须引用本项目文件并提供一致的结果计数。`passed` 要求全部用例执行成功。登记测试以进程退出码记录一次测试入口的成功/失败，并保存 stdout/stderr；它不会解析框架内部用例计数。

## 发布与恢复

候选包含固定提交、SHA-256 制品摘要、关联变更、配置引用、运行手册与恢复手册。每项变更均需当前有效的人工 Review 和通过测试、已确认需求/设计以及待验收状态。

先配置环境目标和配置版本，再预检、负责人批准、执行人登记人工部署。prod 必须已有同一候选在 test 核验，且生产申请人与批准人不能相同。管理员/安全管理员不能代替负责人批准。每个环境最多存在一个 awaiting_evidence 部署。

回传必须包含实际提交、制品摘要、配置版本、环境、外部操作 ID 和报告文件。任一不匹配记录为 failed；仅完全匹配才更新环境版本。回滚接口生成恢复计划，不声称已经执行回滚。

## 审计、备份与恢复演练

JSONL 按日期、容器 hostname 与 PID 分文件，独立 hash chain。查询/导出读取所有授权文件，支持时间、人员、角色、项目、动作、结果、资源类型、关联 ID、事件 ID 和关键字。完整性状态按实际链校验计算；篡改或损坏显示 invalid。查询和导出自身也写入审计。

worker 默认 30 天后将旧 JSONL 压缩归档到同一审计卷 `archive/`，校验成功并记录轮转事件后移除热文件；查询仍读取归档。文件证据默认 retention_until 为 90 天，当前不自动永久删除，避免破坏审批链。更长期外部归档和清理由企业保留策略确定。

```sh
docker/scripts/backup.sh /absolute/path/to/backup
docker/scripts/restore-check.sh /absolute/path/to/backup
```

备份脚本暂停写服务，保存 MySQL 两库 dump、Git 数据/配置、平台文件与审计卷，然后恢复服务；生成 SHA-256 清单。备份目录权限 700、文件 600。workspace 临时 clone 不属于事实源。

恢复脚本在独立、不联网的 MySQL 和新 named volumes 中恢复，不覆盖当前项目。记录还原行数与实际耗时。每次演练保留停止状态的恢复容器/卷供检查；确认无需保留后再由操作者清理。生产切换时需另外恢复连接账号、更新路由/凭证、核验健康与文件 hash，再开放流量；演练耗时不是生产承诺 RTO。

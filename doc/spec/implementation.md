# 实现与验收范围

2026-10-06。此文件记录当前实现，不将设计模拟或测试执行器的回执称为真实生产验收。目标需求仍由 [spec](spec.md) 定义。

## 已实现

- TypeScript API / React / Ant Design 紫色工作台；项目/Intent/Gate/PR/组合/运行/授权/审计/运维采用独立页面和卡片。方案、材料、系统方案提供中文表单，方案可结构化导入。
- Gitea OAuth + PKCE + 同源 Cookie/CSRF；受限身份代理；短时项目委托、Ed25519 回执、角色隔离和撤销。Gitea/MySQL 只在容器内 loopback 监听。
- Gate A 固定分支/方案/快照；Git 包校验、文件范围、快进与受保护引用限制；B 自动创建真实 PR；逐个人工合并、目标漂移检查、最终组合重验；C 绑定已确认生产基线和精确制品；实际回执对账。
- 高风险 B 提交者分离；迁移/权限等风险证明接口；高风险 C 审查会签。热修复按已确认生产基线建线，发布后创建同步 Intent/任务；同步血缘有后端门禁。
- 共享工作区协议和 CLI，outbox / inbox / receipts 独立于业务 source SHA，归档于同仓控制分支。禁止文件批准和越权动作。
- MySQL 持久化、原子业务/审计提交、HMAC 审计链与状态摘要；外部操作先登记，未知结果冻结；Git 推送/分支/合并/控制归档支持确定性对账。
- 一体化 Docker（Node、Gitea、MySQL、s6、运维）；仅 data/backup 两卷。空卷自动初始化、随机账号/密钥/首备、每日03:00、计划修改、手动冷备、保留策略、完整归档校验、新空卷恢复与凭证撤销。恢复演练不启动 Web/任务派发。

## 当前边界与未完成验收项

1. 外部 IDE 控制面和 Runner 是接入契约，不包含用户项目的生产执行程序。集成测试模拟了可信执行器和实际版本文件，没有部署用户生产服务。真实发布前必须接入自己的构建、制品签名、SBOM、隔离测试、实际环境查询及恢复逻辑。
2. 低风险单 PR 完整闭环和 Git 访问边界已做真实集成。多 PR 连续漂移、生产热修复同步、高风险双人会签、运行中撤权、未知操作的全部恢复组合，还需要扩大真实故障矩阵，不能宣称所有 spec 验收已完成。
3. 当前 MySQL 按领域表保存 JSON 实体（含 project_id 索引），用事务、乐观实体比较与完整性签名维持一致性；尚未完成 spec 规划的全部独立规范化表、显式外键、Git blob/修订索引和大日志对象存储。适用目标为少量仓库/小团队，大量历史数据需再优化查询与审计校验。
4. 构建回执已验签并绑定 source/config/dependency/artifact 等字段；生产执行器还应强制证明其固定命令、环境及制品来源。平台不能证明被攻陷的受信执行器内部行为。
5. 同仓协议已可使用；尚未提供 IDE 插件、自动工作树创建和目录持续监视。CLI 显式 sync，不需要两个 agent 互调模型。
6. 运维有同版本恢复和隔离恢复报告；尚未实现跨版本迁移/升级编排、恢复报告导回主实例标注、地址变更向导，以及满盘/归档中断/长时间停机补跑的完整故障演练。禁止直接把旧镜像接入已升级 datadir。
7. 初始化成功、真实备份恢复、浏览器与 API 的具体运行结果以 `doc/test_case/verification.md` 为准。修改实现后应重跑相关检查；不能用本文件替代执行记录。

## 源码入口

`src/server.ts`：认证、身份代理与 API；`control.ts`：Gate/证据/交付；`gateway.ts`/`git.ts`：Git 校验与 Gitea；`store.ts`：MySQL/审计；`ops.ts`/`backup.ts`：初始化、备份、恢复；`safety.ts`：验签、重启/租约处理；`web/src`：人类工作台；`cli/devops.mjs`：文件同步。

# 实现与验收范围

2026-10-07，schema 2。DevOps 现仅管理需求与版本，旧执行与审批控制面已删除。

已实现统一身份、需求修订与直接状态编辑、Git 唯一入口、工作分支/PR/合并/不可变标签、项目委托、需求文件同步、连续审计，以及平台双卷冷备。创建项目仅需名称，导入会真正保留源码、二进制、执行位和原始 agent.md。API/E2E 编写、运行和发布由 IDE Agent 自行负责，没有 Runner 接入或执行证明回传。

旧 schema 1 的完整快照写入 legacy_archive，项目、需求文字、已知分支/PR 提取到新模型，旧凭证与会话撤销；业务 Git 历史保留。历史方法论文档注明已被新版范围取代。

本仓库提供 Web、Git HTTP、需求/版本 API 和共享目录 CLI。独立 IDE 产品与自动测试/发布工具不在本仓库。压缩包支持 ZIP/TAR（可 gzip/bzip2/xz 压缩），不支持 RAR/7z 等其他格式。工作分支只允许快进，Git 网关拒绝符号链接和子模块变更。main 保护只关闭直接推送，不要求工作分支先更新到最新 main；合并前的唯一内容门禁是 DevOps 的真实冲突检测。

Git 与数据库没有跨服务事务。未知结果先保存审计，不重复执行原请求；核对仓库根据实际引用补齐结果。若首次推送已存在，可以完成中断的控制分支与保护初始化；若连首次提交都未写入，需管理员检查仓库，不能凭空恢复原上传文件。控制分支投影失败会标记待同步，权威需求仍在数据库中。

API 测试使用适配器；真实集成使用 Gitea/MySQL。最终测试证据和运行限制见 [验证记录](../test_case/verification.md)。未把 IDE 自述的测试或部署结果当作本产品的验证结果。

# 序 · AI 原生 DevOps 产品验收

依据 [方法论](AI原生DevOps轻量方法论.md) 与 [规格](../spec/spec.md)。本文件定义实际人类操作路径，供前端完成后编写 E2E。视觉以 agent.md 为准：紫色、浅色工作区、卡片列表、独立页面。

1. 未登录时展示明确的统一账号入口和首次启动提示。登录使用内置 Gitea 的用户名密码；内置账号为 `admin/admin`，平台不支持 Passkey/WebAuthn。继续使用默认密码时，进入 DevOps 后每次提示修改密码，用户可以选择“本次忽略”。
2. 空工作区不显示虚构数据。管理员创建项目，填写独立验收环境、发布环境、固定命令 ID 和 Runner 身份。
3. 创建 Intent 后进入详情页，准备点方案和应用方案；Gate A（方案确认）分为缺口、固定对象、理由确认三个步骤。签发后显示真实工作分支、基线和快照。
4. 证据缺失时 Gate B（交付候选确认）明确列出构建、unit/component/security/API/E2E 缺口，不能签发。内容改变使旧批准失效。
5. 通过 Gate B 后出现真实 PR。独立合并页显示差异和目标 SHA，填写理由后逐个合并。组合页显示完整应用集合和重新验收要求。
6. 系统方案与制品、环境、最终 SHA 一致才可签 Gate C（发布确认）。页面不提供平台直接部署按钮；发布由外部 IDE 预设逻辑完成，实际回执显示在交付页。
7. 项目授权页签发一小时凭证，仅展示一次原文，可撤销；IDE 控制面/Runner 需要 Ed25519 公钥，不能以人类凭证冒充执行回执。
8. 运行页展示操作状态，UNKNOWN 进入独立对账页面。审计页可查操作者与关联记录。
9. 系统运维展示当前状态、默认每日 03:00 计划、首备和最近归档；手动备份先提示维护窗口。
10. 390px 窄屏不产生横向溢出，导航、确认步骤和主要按钮可用。错误、空态和加载态有可读反馈。
